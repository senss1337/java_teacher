## Что изучить до старта

### 1. Как работают сессии и куки

**Простыми словами.** HTTP не помнит пользователя: каждый запрос сам по себе. Чтобы после логина сервер «узнавал» тебя,
используется связка **сессия + кука**:

```
Браузер                                       Сервер                           БД
  │ POST /sign-in  login=ann&password=...      │                                │
  │ ─────────────────────────────────────────> │ проверить пароль               │
  │                                            │ создать сессию (id=UUID,       │
  │                                            │   userId=7, expiresAt=+24h) ──>│ INSERT sessions
  │ 302 Location: /                            │                                │
  │ Set-Cookie: SID=3f2a...; HttpOnly; ...     │                                │
  │ <───────────────────────────────────────── │                                │
  │                                            │                                │
  │ GET /                                      │                                │
  │ Cookie: SID=3f2a...                        │                                │
  │ ─────────────────────────────────────────> │ найти сессию 3f2a, не истекла? │
  │                                            │ userId=7 → это Ann        <──── │ SELECT
  │ 200 <html>Привет, Ann</html>               │                                │
```

- **Кука** — пара «имя=значение», которую сервер просит браузер хранить (`Set-Cookie`), и браузер присылает её
  с каждым запросом (`Cookie`). В куке — **только ID сессии**, никаких данных пользователя.
- **Сессия** — запись на сервере (у нас в таблице `Sessions`): ID, пользователь, срок годности.
- **Logout** — удалить сессию на сервере (и попросить браузер удалить куку).

**Атрибуты куки** — важны для безопасности:
- `HttpOnly` — JavaScript на странице не может прочитать куку (снижает вред от XSS);
- `Secure` — только по HTTPS;
- `SameSite=Lax` — не отправлять куку в запросах, пришедших с чужих сайтов (защита от CSRF);
- `Max-Age` — срок жизни; `Path=/` — для каких путей.

**В Java/Spring**: прочитать куку — `@CookieValue("SID") String sid` или `request.getCookies()`; установить —
`ResponseCookie.from("SID", id).httpOnly(true)...build()` → заголовок `Set-Cookie`.

**Где проверять сессию.** Не в каждом методе контроллера (копипаста!), а один раз для всех защищённых путей:
- `HandlerInterceptor` (Spring MVC) — метод `preHandle` вызывается до контроллера; может отказать или положить
  пользователя в атрибут запроса;
- `Filter` (сервлетный уровень, ты знаешь его по проекту 3).

А чтобы контроллер получал текущего пользователя параметром (`public String home(User user)`), есть
`HandlerMethodArgumentResolver`. Это очень элегантно, разберись.

### 2. Пароли и веб-атаки

**Пароли.** Хранить пароль открытым текстом нельзя: при утечке БД все пароли у злоумышленника. Хранят **хеш**.
Но не SHA-256: он быстрый, видеокарта перебирает миллиарды вариантов в секунду. Нужна **медленная** функция с **солью**
(случайная добавка к каждому паролю, чтобы одинаковые пароли давали разные хеши) — **BCrypt**. Соль и «стоимость» (cost)
хранятся прямо в строке хеша.

```java
// библиотека spring-security-crypto (только крипто, без Spring Security) или jBCrypt
var encoder = new BCryptPasswordEncoder();
String hash = encoder.encode("qwerty");           // $2a$10$N9qo8uLOickgx2ZMRZoMye... — каждый раз разный
encoder.matches("qwerty", hash);                  // true
```

**Атаки, о которых надо знать:**
- **XSS** — злоумышленник подсовывает `<script>` в данные (например, в название локации), и он выполняется у других.
  Защита: экранирование вывода. В Thymeleaf `th:text` экранирует, `th:utext` — нет (с пользовательскими данными запрещён).
- **CSRF** — чужой сайт заставляет браузер жертвы отправить форму на твой сайт, и кука уйдёт автоматически.
  Защита: `SameSite`, CSRF-токены в формах.
- **Session fixation** — атакующий заранее «подсовывает» жертве известный ему ID сессии. Защита: при логине всегда
  создавать **новую** сессию.
- **Перебор ID сессий** — ID должен быть непредсказуемым (`UUID.randomUUID()` использует криптостойкий генератор — проверь в Javadoc).

> 🎯 **Спросят на собесе:** Почему пароли хешируют BCrypt, а не SHA-256?
> **Ответ:** SHA-256 быстрый — это плохо для паролей: перебор миллиардов вариантов в секунду на GPU. BCrypt/scrypt/Argon2
> специально медленные (настраиваемый cost), содержат соль (защита от rainbow tables) и хранят её в самом хеше.

> 🎯 **Спросят на собесе:** Что такое session fixation и как защититься?
> **Ответ:** Атакующий навязывает жертве известный ему ID сессии до логина; после логина жертвы сессия становится
> аутентифицированной. Защита — выдавать **новый** ID сессии при аутентификации.

> 🎯 **Спросят на собесе:** Что делают `HttpOnly` и `SameSite`?
> **Ответ:** `HttpOnly` — кука недоступна из JavaScript (снижает ущерб от XSS). `SameSite=Lax/Strict` — кука не
> отправляется в кросс-сайтовых запросах (защита от CSRF).

### 3. Thymeleaf и формы

**Простыми словами.** Thymeleaf — шаблонизатор HTML, как Jinja2. Контроллер кладёт данные в `Model` и возвращает имя
шаблона; Thymeleaf подставляет данные в HTML.

```html
<!-- templates/books.html -->
<ul>
  <li th:each="book : ${books}" th:text="${book.title}">Пример</li>   <!-- th:text экранирует -->
</ul>
<form th:action="@{/books}" th:object="${form}" method="post">
  <input th:field="*{title}"/>
  <span th:if="${#fields.hasErrors('title')}" th:errors="*{title}"></span>
</form>
<div th:replace="~{fragments/header :: header}"></div>                  <!-- общий заголовок -->
```

**PRG (Post/Redirect/Get).** После успешной обработки формы отвечай редиректом (`return "redirect:/"`), а не HTML.
Иначе F5 повторно отправит форму.

### 4. Внешнее API за своим интерфейсом (Adapter / Gateway)

**Простыми словами.** OpenWeather возвращает большой JSON со своими названиями полей и температурой в Кельвинах.
Если этот формат расползётся по контроллерам и шаблонам, то смена провайдера погоды (или даже версии API) затронет всё
приложение. Правило: **чужая модель не проникает в твой код**.

- Твой код зависит от **своего** интерфейса («сервис погоды») и **своих** моделей (локация, погода в °C).
- Один класс-**адаптер** знает про OpenWeather: делает HTTP-запросы, разбирает их JSON в DTO OpenWeather
  и **переводит** в твои модели. DTO OpenWeather — только внутри адаптера.

```java
// Нейтральный пример: курс биткоина из внешней биржи
interface PriceProvider { Price current(Symbol s); }                   // СВОЙ контракт, СВОЯ модель
class ExchangeXAdapter implements PriceProvider {                       // единственный, кто знает про биржу X
    public Price current(Symbol s) {
        ExchangeXTickerDto dto = restClient.get()
                .uri("/ticker?pair={p}", s.code() + "USDT")
                .retrieve().body(ExchangeXTickerDto.class);
        return new Price(s, new BigDecimal(dto.lastPrice()));            // перевод в свою модель
    }
}
```

**HTTP-клиент.** В Spring 6.1+ — `RestClient` (как `requests`); ещё есть `java.net.http.HttpClient` из JDK.
Обязательно: **таймауты** (иначе зависший API повесит твои потоки), **URL-кодирование** параметров (город «Нижний Новгород»),
разбор **ошибок** (4xx/5xx → твои исключения). Jackson: `@JsonIgnoreProperties(ignoreUnknown = true)`, чтобы не падать
на лишних полях, `@JsonProperty("feels_like")` для имён в snake_case.

**Секрет API-ключа** — только из переменной окружения, не в коде и не в `application.properties` в git.

### 5. Профили и конфигурация Spring

**Простыми словами.** Для разработки, тестов и продакшена нужны разные настройки (БД, время жизни сессии, ключи).
Код одинаковый, меняется конфиг. В Spring это **профили**: `application-dev.properties`, `application-test.properties`;
активный профиль — `spring.profiles.active=dev` (или переменная окружения `SPRING_PROFILES_ACTIVE`).
Бины можно включать только в определённом профиле: `@Profile("test")`. Без Boot: `@PropertySource` + `Environment`.

### 6. Миграции БД: Flyway

**Простыми словами.** Как Alembic или Django migrations: схема БД описана версионированными SQL-файлами
`V1__create_users.sql`, `V2__create_locations.sql`... При старте Flyway смотрит в служебную таблицу
`flyway_schema_history`, какие уже применены, и накатывает новые. Правила:
- **никогда не меняй уже применённую миграцию** (Flyway заметит изменение контрольной суммы и откажется стартовать):
  нужна правка — новая миграция;
- Hibernate схему не создаёт: `hibernate.hbm2ddl.auto=validate` (только проверить соответствие).

### 7. Интеграционные тесты и моки

**Простыми словами.**
- **Юнит-тест** проверяет один класс в изоляции (проект 4, домен).
- **Интеграционный** — связку: сервис + настоящая БД, или сервис + HTTP-клиент.

Для тестов с БД нужна **отдельная** база/схема, которая очищается перед каждым тестом, иначе тесты влияют друг на друга.
Spring Test поднимает контекст (`@SpringJUnitConfig`), `@ActiveProfiles("test")` включает тестовый конфиг.

Для внешнего API — **никаких реальных запросов** в тестах: они медленные, зависят от сети и тратят лимит. Подменяем:
- **Stub** — возвращает заготовленный ответ;
- **Mock** — ещё и проверяет, что его вызвали правильно;
- **Fake** — упрощённая рабочая реализация (репозиторий на `HashMap`).

Для HTTP в Spring есть `MockRestServiceServer`: «на запрос к такому URL верни вот этот JSON со статусом 200/500».
Альтернатива — WireMock (настоящий локальный HTTP-сервер с заготовками).

```java
// Нейтральный пример: тест адаптера биржи без реальной биржи
server.expect(requestTo(containsString("/ticker?pair=BTCUSDT")))
      .andRespond(withSuccess("""
          {"lastPrice": "65000.12", "volume": "..."}
          """, MediaType.APPLICATION_JSON));
Price p = adapter.current(Symbol.BTC);
assertThat(p.value()).isEqualByComparingTo("65000.12");
```

**Время в тестах.** Истечение сессии через `Thread.sleep` — медленно и ненадёжно. Если сервис берёт время из `Clock`
(тема 10 модуля 0′), в тесте подставляешь `Clock.fixed(...)` или сдвигаемые часы.

> 🎯 **Спросят на собесе:** Mock vs Stub vs Fake?
> **Ответ:** Stub возвращает заготовленные ответы. Mock — ещё и проверяет взаимодействия (какие методы вызваны и с чем).
> Fake — рабочая упрощённая реализация (in-memory репозиторий). Мокай то, что тебе не принадлежит, только на границах.

## Паттерны и принципы в фокусе

- **Adapter / Gateway** для внешнего API + **Anti-Corruption Layer**: чужая модель не проникает в домен.
- **Interceptor / Filter** — сквозная функциональность (аутентификация) отдельно от бизнес-логики.
- **Template View** (Thymeleaf) + **PRG**.
- **Конфигурация профилями** — окружения отличаются конфигом, а не кодом.
